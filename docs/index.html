UX research · eye tracking · vision-language models

Where people look versus where the task needs them to look.

GazeGrounded UX tests whether the gap between human visual attention and a task-aware vision-language model's estimate of the task-relevant interface regions can reveal friction in user interfaces — and explains it with gaze, behaviour and what participants say.

The idea

Usability tests show that people struggle. Eye tracking shows where they looked. A vision-language model, given the screenshot and the task, can estimate where the task-relevant information is. Comparing the two points to why: the control exists but isn't found, is found but not recognised, or attention is pulled elsewhere.

Human gaze

Fixations, time to first look at the target, revisits, scanpaths and heatmaps from raw gaze samples.

Task-aware model

A vision-language model reads the screenshot and the task and returns the relevant elements with boxes and scores — a map of where the task needs attention.

Friction

Divergence between the two, combined with behaviour and written feedback, predicts friction level and points to its likely cause.

Failure cases

Method and limits

How the numbers are produced and what they cannot tell you.

Measures

I-DT fixation detection; AOIs padded by tracker accuracy; time to first fixation on the target, revisits, transitions; duration-weighted heatmaps. Early divergence = Jensen–Shannon divergence between the first 8 fixations and the model map. Whole-trial divergence is confounded by the number of fixations.

Evaluation

Grouped cross-validation by participant and by interface; majority-class reference; macro-F1 and weighted kappa. Statistics treat trials as nested in participants (repeated-measures correlation, paired tests on participant means, Holm correction). Analyses are fixed before data collection.

Limits

The model map is an estimate of task-relevant regions, not a measurement of attention. Gaze shows where people looked, not what they understood. Webcam eye tracking is far less precise than lab trackers. Static screenshots stand in for live, multi-step interfaces.

Study design

Nine fictitious interfaces (checkout, banking, travel, patient portal, subscription), each with a clean and a friction variant except one. Participants see one variant of each pair (counterbalanced), complete 9 tasks with webcam eye tracking, rate ease (SEQ) and comment. No video is recorded; only gaze coordinates, clicks and answers are kept.

Privacy

Pseudonymous participant codes, no names or e-mails, nothing uploaded automatically: participants download their own data and send it to the researcher. Gaze is treated as sensitive behavioural data.

Run it locally

Python 3.11+. The demo runs on a laptop in about a minute and costs nothing.

1. Install

git clone https://github.com/<owner>/GazeGrounded-UX.git
cd GazeGrounded-UX
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

2. Run the pipeline and open the dashboard

python -m gazegrounded.cli run-all     # synthetic demo, ~1 min
streamlit run dashboard/app.py         # interactive dashboard

3. Use your own data

# webcam study (stimuli + tasks.json), then serve locally
python -m gazegrounded.cli build-study
cd study/webgazer && python -m http.server 8000

# analyse collected sessions in data/raw/study/sessions/
python -m gazegrounded.cli run-all --config configs/experiment.yaml

# use a local vision-language model (Qwen2.5-VL)
pip install -e ".[vlm]"
python -m gazegrounded.cli vlm-analysis --set vlm.provider=local

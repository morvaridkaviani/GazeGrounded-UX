# Data

Nothing in this folder is committed except this README. All data is either generated locally
(synthetic demo) or obtained by you under its own licence.

```text
data/
├── synthetic/              generated by `gazegrounded.cli generate-demo`
├── raw/                    external data you obtain (never committed)
│   ├── ueyes/UEyes_dataset/
│   └── study/              your own WebGazer study exports
├── interim/<source>/       fixations, gaze metrics, VLM outputs, NLP predictions
│   └── vlm_cache/          cached raw VLM responses (keyed by image hash, task, model, prompt)
└── processed/<source>/     standardised, validated tables + features.csv
```

## Standard schema

Adapters convert every source into the same tables
(`src/gazegrounded/data/schemas.py`; column-level definitions in
[study/data_dictionary.md](../study/data_dictionary.md)):

| Table | Unit | Key columns |
|---|---|---|
| `uis` | screenshot | `ui_id`, `image_path`, `width`, `height`, `condition`, `pair_id` |
| `aois` | area of interest | `ui_id`, `aoi_id`, normalised `x_min…y_max`, `semantic_role` |
| `tasks` | task on a UI | `task_id`, `ui_id`, `task_description`, `target_aoi_ids` |
| `trials` | participant × task | success, completion time, errors, clicks, feedback, friction label |
| `gaze_samples` | raw sample | `trial_id`, `timestamp_ms` (since stimulus onset), `gaze_x/y` (px), `validity` |
| `fixations` | fixation | only for sources that ship fixations instead of samples (UEyes) |

## 2. UEyes (free-viewing eye tracking on UI screenshots)

* Paper: Jiang et al., *UEyes: Understanding Visual Saliency across User Interface Types*,
  CHI 2023. Code: <https://github.com/YueJiang-nj/UEyes-CHI2023>.
* Data: Zenodo record 10.5281/zenodo.8010312 (`UEyes_dataset.zip`, ~12.9 GB),
  licence **CC BY 4.0** (attribution required). The code repository has no licence file.
* 1,980 screenshots (web, desktop, mobile, poster; 495 each), 62 participants, 7 s free viewing,
  Gazepoint GP3 at 60 Hz, 1920 × 1200 display.

Unzip so that this path exists: `data/raw/ueyes/UEyes_dataset/image_types.csv`. Then:

```bash
python -m gazegrounded.cli preprocess     --config configs/ueyes.yaml
python -m gazegrounded.cli gaze-analysis  --config configs/ueyes.yaml
python -m gazegrounded.cli train-saliency --config configs/ueyes.yaml --device mps
```

Adapter notes (`UEyesAdapter`):

* `image_types.csv` is `;`-separated (`Image Name;Category;Block;Train/Test`).
* Logs are `eyetracker_logs/{block}_{kh|KH}{participant}_fixations.csv`; there is no participant
  column, so the ID comes from the file name. Lock files and `__MACOSX` copies are skipped.
* `FPOGX/FPOGY` are fractions of the **screen**, on which the image was letterboxed. They are
  mapped to image pixels the way the dataset's own heatmap script does
  (`coordinate_frame="screen_letterbox"`). The repo's log parser instead multiplies by the
  image size; that reading is available as `coordinate_frame="image"`. Check a few overlays
  before relying on either.
* Some image files have extensions that don't match their format; Pillow detects the format
  from the content.
* UEyes has no tasks, interaction logs or friction labels. It supports the gaze pipeline and the
  saliency model, not the friction model.

## 3. Your own study (WebGazer)

See [study/README.md](../study/README.md). After collecting sessions:

```text
data/raw/study/
├── sessions/*.json       one export per participant (from the browser study)
├── labels.csv            optional: trial_id, friction_label[, feedback_category]
├── tasks.json            copy of study/webgazer/tasks.json used during collection
└── stimuli/              copy of study/webgazer/stimuli/
```

```bash
python -m gazegrounded.cli run-all --config configs/experiment.yaml
```

Labels: researcher-coded `labels.csv` is preferred (`label_source = human_coded`). Without it,
the participant's ease rating (SEQ) is mapped to low/medium/high (`self_report_seq`). That is
self-reported difficulty, which is a different construct from observed friction, and should be
reported as such.
